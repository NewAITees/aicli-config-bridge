# test-requirements

## 手順

1. テスト対象の関数・モジュールを特定する
2. 次の5観点で要件をリスト化する:
   - 正常系
   - 境界値(上限・下限)
   - エッジケース
   - 例外パス
   - 形式・型
3. 「形式・型」だけの要件は主要項目から除外する
   (例: 「`age`はnumber型」ではなく「`age`が負なら`InvalidAgeError`を返す」まで書く)
4. 要件リストを提示してから、テストコードを書く
5. 監査フェーズ: 要件のうちテストが対応していないもの、逆に要件と紐づかない
   テスト、形式だけのテストの比率を確認して報告する

## `feedback-loop`スキルとの関係

`test-requirements`は「何をテストすべきか」を決める前工程、
`feedback-loop`はその要件を入力にRed/Green/Refactorで実装する後工程。
両者は独立させたまま連携させる。

## 禁止事項

- 分岐のない単純なgetter・setterには適用しない(過剰発動を避ける)
- 形式・型だけの要件を主要リストに残さない
