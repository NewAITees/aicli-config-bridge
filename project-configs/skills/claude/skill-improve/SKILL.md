# Skill Improve — スキル改善メタスキル

スキルは使うことで初めて改善できる。このスキルは「直前に動かしたスキルがどうだったか」を振り返り、スキル定義・共有概念・学びを更新する。改善のループを回さなければ、スキルは最初のバージョンから成長しない。

## Step 1: スキルの振り返り

直前に使ったスキルについて以下を確認する。

**うまくいったか：**
- 期待通りの結果が出たか？
- スキルの手順は自然に流れたか？
- 省略・スキップしたステップはあったか？それは妥当だったか？

**うまくいかなかったか：**
- どのステップで詰まったか？
- なぜ詰まったか？（スキルの指示が曖昧 / 前提が違った / 想定外のケース）
- 次回同じ状況でどうすれば改善できるか？

## Step 2: 概念・用語のズレを記録する

「これをやって」と言ったときにAIの解釈が意図と違った場合、その概念のズレを記録する。

`alignment.md`（プロジェクトルートまたは `tasks/` 直下）に追記する：

```markdown
## [概念名]
- **ユーザーの意図**:
- **AIの解釈（ズレていた場合）**:
- **正しい定義**:
- **記録日**:
```

`alignment.md` が存在しない場合は新規作成する。このファイルはセッション冒頭に読み込むことで、AIとの共有理解を蓄積する。

## Step 3: lessons.md を更新する

失敗・学びがあった場合は `tasks/lessons.md` に追記する。

```markdown
### [タイトル（キーワードを含む1行）]
- **症状**:
- **原因**:
- **対策**:
```

「次回の自分が同じ失敗をしないために何を知っておけばよいか」を書く。

## Step 4: スキル定義を更新する

振り返りの結果、スキルの手順・表現・チェックリストに改善点があれば、スキルファイルを直接編集する。

- 曖昧だった指示を具体化する
- 不要なステップを削除する
- 見落としていたケースを追加する
- `~/.claude/skills/<skill-name>/SKILL.md` を編集する

**判断基準：**
- 同じ問題が2回起きたら必ず修正する
- 「たぶん大丈夫」で修正しないのではなく、小さくても改善する

## Step 5: architectスキルを走らせるべきか判断する

以下に該当する場合は `architect` スキルの実行を提案する：

- 実装が積み重なってきた（3回以上の実装サイクルを経た）
- ファイルが肥大化してきた感覚がある
- 似た処理を何度か書いた気がする

## 原則
- このスキルは「完璧な振り返り」を目指さない。気づいた点を素早く記録することが目的
- 振り返りに時間をかけすぎない。5〜10分で終える
- 記録は未来の自分とAIへの手紙として書く
