# codex-implement

## 位置づけ

`delegate`スキル(agent-wrapper)は非同期・ダッシュボード承認前提で、長時間タスクや
承認ゲートが必要な規模の作業向け。日常的な「この仕様通りに実装して」レベルの
作業にはダッシュボード起動・ポート確認・Ollama前提が重すぎる。

このスキルは、その場で完結する軽量版: `codex exec`を同期呼び出しし、
実装はCodexに、最終レビューはClaudeに分担する。

## 前提

- `codex` CLIが使えること(`codex --version`)
- 対象ディレクトリがgit管理下で、作業ツリーがクリーンであること
- 実装対象の仕様が明確であること。曖昧なら先に`/spec`で固める(このスキルを
  曖昧な仕様のまま使わない)

## 手順

### 1. 呼び出し前チェック

```bash
git status
```

汚れていれば、先にコミット可能な状態にするかユーザーに確認する
(Codexの変更を丸ごと切り戻せるようにするため)。

### 2. 実装をCodexに委任

```bash
codex exec --skip-git-repo-check -s workspace-write -C "$(pwd)" "$(cat <<'EOF'
以下を実装してください。

[仕様・設計の内容をここに含める]

制約:
- 既存テストを壊さない。新機能にはテストを追加する
- git commit は行わない
- 要求以上の機能・抽象化を追加しない
- 既存のdocstring・設計コメントを削除しない
EOF
)"
```

失敗時は最大2回再試行(2秒/5秒の指数バックオフ)。3回失敗したらClaude自身が実装する。

### 3. Codexに説明させる(説明役)

実装後、Codex自身に変更内容を平易な日本語で説明させる。

```bash
codex exec --skip-git-repo-check "直前に変更したファイルについて、
何を・なぜ変更したか、ロールバック方法を含めて日本語で平易に説明してください。

$(git diff)
"
```

この説明はレビューの参考情報として使うが、正当性の根拠にはしない
(実装者本人の自己申告であり、過小評価・見落としがあり得るため)。

### 4. Claudeによるレビュー(必須、Codexの報告を鵜呑みにしない)

1. `git diff`全体を自分で読む
2. `uv run pytest` / `ruff check` / `mypy`(プロジェクトに応じたテスト・lint・型チェック)を自分で実行する
3. 手順3のCodexの説明と実際の差分が一致しているか照合する
4. 問題があれば自分で修正するか、手順2をやり直す

### 5. コミット

問題なければ、ユーザーの明示的な依頼(y/n)を得てからコミットする。

## 禁止事項

- Codexの完了報告・説明を鵜呑みにして無検証でコミットしない
- 曖昧な仕様のままこのスキルを使わない(先に`/spec`)
- 承認ゲートが必要な大規模・長時間タスクには使わない(その場合は`delegate`スキル)
