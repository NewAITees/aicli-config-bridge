# codex-implement

## 位置づけ

`delegate`スキル(agent-wrapper)は非同期・ダッシュボード承認前提で、長時間タスクや
承認ゲートが必要な規模の作業向け。日常的な「この仕様通りに実装して」レベルの
作業にはダッシュボード起動・ポート確認・Ollama前提が重すぎる。

このスキルは、その場で完結する軽量版。`codex` CLIを自前で直接呼ぶのではなく、
既にインストール済みの`codex`プラグインが提供する`/codex:rescue`
(codex-companionランタイム、リトライ・バックグラウンド実行・スレッド再開を内蔵)
を使う。実装はCodexに、最終レビューはClaudeに分担する。

## 前提

- `codex`プラグインが有効であること(`/codex:setup`で確認可能)
- 対象ディレクトリがgit管理下で、作業ツリーがクリーンであること
- 実装対象の仕様が明確であること。曖昧なら先に`/spec`で固める(このスキルを
  曖昧な仕様のまま使わない)

## 手順

### 1. 呼び出し前チェック

```bash
git status
```

汚れていれば、先にコミット可能な状態にするかユーザーに確認する
(Codexの変更を丸ごと切り戻せるようにするため)。

### 2. 実装とCodex自身の説明を1回のrescueで依頼

`/codex:rescue`(既定で`--write`、書き込み可能)に、実装内容と「完了後に
変更点を日本語で説明すること」を1つのタスク文としてまとめて渡す。

```
/codex:rescue [仕様・設計の内容]

制約:
- 既存テストを壊さない。新機能にはテストを追加する
- git commit は行わない
- 要求以上の機能・抽象化を追加しない
- 既存のdocstring・設計コメントを削除しない

完了したら、何を・なぜ変更したか、ロールバック方法を日本語で平易に説明すること。
```

- タスクが小さく明確なら既定(フォアグラウンド)のまま
- 大きい・多段階・長時間になりそうなら`--background`を付ける
- 前回のCodex作業の続きなら`--resume`、新規なら明示不要(既定で新規)

Codexからの説明はレビューの参考情報として使うが、正当性の根拠にはしない
(実装者本人の自己申告であり、過小評価・見落としがあり得るため)。

### 3. Claudeによるレビュー(必須、Codexの報告を鵜呑みにしない)

**`/codex:review`は使わない**(Codexが自分の実装を自分でレビューする
自己レビューになり、別のAIによるクロスチェックにならないため)。

1. `git diff`全体を自分で読む
2. `uv run pytest` / `ruff check` / `mypy`(プロジェクトに応じたテスト・lint・型チェック)を自分で実行する
3. 手順2でCodexが返した説明と実際の差分が一致しているか照合する
4. 問題があれば自分で修正するか、手順2をやり直す(続きの場合は`--resume`)

### 4. コミット

問題なければ、ユーザーの明示的な依頼(y/n)を得てからコミットする。

## 禁止事項

- Codexの完了報告・説明を鵜呑みにして無検証でコミットしない
- 曖昧な仕様のままこのスキルを使わない(先に`/spec`)
- 承認ゲートが必要な大規模・長時間タスクには使わない(その場合は`delegate`スキル)
- レビューに`/codex:review`・`/codex:adversarial-review`を使わない(自己レビューになるため。
  それらはClaude自身が実装したコードのセカンドオピニオンが欲しい場面で使う)
